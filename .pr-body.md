## Problem

Per-crate audit follow-up for `convergio-planner` (plan
`ccbb7523-16b6-44b3-aa63-caa91a5bc095`). The audit report at
`docs/reviews/crate-audits/convergio-planner.md` flagged 4 medium + 3 low
findings. All of them must be validated against current code, then
either fixed, marked false-positive, or deferred with a reason.

## Why

The audit lives on `main` as a snapshot. Several findings reference a
state of the tree that has since been improved (the audit baseline
predates `e6a57b7 feat(planner): opus-backed planner` follow-ups). Both
behavioral fixes that were genuinely needed (string-aware JSON
extractor, sequence-zero validation) had to land with reproducer tests
first per the operating contract; the textual drift fixes (README +
AGENTS.md invariant) landed as `docs(planner):`.

## What changed

Three commits sitting on this branch ahead of `main`:

- `d323991 test(planner): reproduce brace-in-string parse + sequence validation`
- `3b576e9 fix(planner): respect json strings in extractor; validate sequence`
- `d195aee docs(planner): document opus default + rephrase provider invariant`
- `c9833ba chore(repo): regenerate auto doc blocks`

The behavioral fixes:

- `extract_json_object` now uses `serde_json::Deserializer::into_iter`
  to find the end of the first object, so `{` / `}` inside JSON
  strings no longer truncate the payload. New regression test
  `parse_response_tolerates_braces_inside_strings`.
- `PlanShape::validate` now rejects `sequence < 1` (was already
  rejecting `wave < 1`). New regression tests
  `validate_rejects_sequence_zero` and
  `validate_rejects_negative_sequence`.

The doc fixes:

- `README.md` rewritten to describe the `auto` / Opus default and the
  heuristic fallback (the legacy line-split description is gone).
- `crates/convergio-planner/AGENTS.md` invariant reworded: the
  reference Opus backend MAY name vendor CLIs and recommend specific
  provider/model combinations; *additional* provider-specific planning
  logic must ship as a capability.

## Impact

- Restores zero-tolerance compliance for planner output (sequence
  validation P1 / zero-tolerance principle).
- Removes the brace-counter regression class — any future title /
  description containing `{` or `}` parses correctly.
- Docs no longer lie about which backend ships by default.
